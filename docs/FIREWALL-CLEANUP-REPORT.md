# Firewall & Cleanup implementation report

The new native WordPress admin screen is `admin.php?page=gracewell-security-suite-pro-firewall-cleanup`. Its layout follows the supplied Firewall & Cleanup reference and reuses the completed Pro header, illustration, icons, tokens and components. Screenshot statistics were replaced with real records. Existing completed page templates, styles and controllers are unchanged.

## Requested delivery report

1. **Files inspected.** Admin registration and AJAX dispatch; plugin bootstrap; Settings, Login Protection, Hardening, Activity Logger, DB, File Integrity, Scan Engine, Malware Analyzer, Security Runtime, PathGuard, Guardian and Quarantine Manager services; existing Dashboard/Two-Factor templates, shared icon sprite, Pro CSS, core JavaScript and Two-Factor header controller; scanner/security/workflow documentation and tests; uninstall retention behavior. The audit found no existing general WAF, GeoIP service, generic request limiter or custom-rule engine.
2. **Files modified.** `gracewell-security-suite-pro.php` loads/registers the new service. `includes/class-gwqsh-admin.php` registers the page and enqueues its assets. `includes/class-gwqsh-ajax.php` adds two actions through its existing nonce/capability dispatcher. These are the only modified pre-existing files.
3. **Files created.** `includes/class-gwqsh-firewall.php`, `admin/views/firewall-cleanup.php`, `assets/css/scoped/pro-firewall-cleanup.css`, `assets/js/firewall-cleanup.js`, `tests/FirewallPageTest.php`, and this report.
4. **UI components.** Eight-item header with the Firewall & Cleanup active state, real WordPress submenu, lighthouse hero and secondary message, five metrics, WAF card and five tabs, native switches, navy Save button, scanner/ring/checklist, four result cards and truthful status banner, denial table and pagination, cleanup tools and versioned footer. Two visual comparison/refinement passes corrected shared CSS specificity, button/heading styling, illustration slogan masking and card density. A formatting-induced attribute whitespace defect was caught and corrected before delivery; result counts and cleanup buttons were reverified.
5. **WAF backend.** Added an opt-in, deliberately limited public query firewall. It starts disabled. Its one `init` hook checks current persisted configuration and plugin activation, excludes authenticated/admin/cron requests, and respects the existing trusted-IP allowlist. No competing login or XML-RPC engine was added. Master/rule changes persist through the existing secure AJAX dispatcher. Disabling active query or login protection requires confirmation.
6. **Rules.** SQL detection correlates a quote/boolean/comment shape or a UNION SELECT numeric/NULL column-list shape. XSS detection looks for script/event-handler query payloads, rather than every HTML character. Scanner agents require a sensitive exploit path; user agent alone never blocks. Rules inspect at most 64 scalar values, 16 KiB total and 2 KiB per value, with one extra decoding pass. Bodies, password fields and authenticated editor content are excluded. These are narrow local signatures, not a comprehensive exploit detector.
7. **IP blocking.** The tab displays up to 25 real active login lockouts with attempts/expiration and nonce-protected, confirmed unlock actions. It previews up to 50 actual allowlist exceptions and links to the existing full Login Protection manager. Existing IPv4/IPv6/CIDR matching is reused. Permanent site-wide IP bans are explicitly unavailable. There are no fake addresses or browser-authored server rules.
8. **Country blocking.** No provider/database exists. The tab explains that no geographic rules are enforced; the metric is zero and explains the missing GeoIP provider. Country attribution is Unknown. No external lookup or visitor country header is trusted.
9. **Rate limiting.** Displays the actual authentication threshold, counting window and lockout duration and links to the shared configuration. General HTTP/API/probe rate limiting is unavailable. No new race-prone counter or misleading switch was created.
10. **Custom rules.** Explicitly unavailable. No PHP editor, eval or executable condition language was introduced.
11. **Scanner integration.** Full Scan uses the existing `run_scan` AJAX action, `GWQSH_File_Integrity` coordinator and `GWQSH_Scan_Engine`. Only its actual supported full mode is offered. The existing eight-second batch budget, locks and cron continuation remain authoritative. Start and Re-scan use the same function and backend.
12. **Progress.** Uses persisted file offset/manifest length and the next file's actual scope. In-progress percentages stay below 100 until completion; no timer invents progress. Continuations use `resume=1`, preserving the existing protection against starting another scan after cron completes. Controls disable during the job; the loop stops on completion/failure/page exit. Checklist items describe supported scanner coverage, not fabricated phase completion.
13. **Results.** SQL aggregates classify current unresolved evidence: Critical heuristic findings as Malware, other Suspicious findings as Suspicious, integrity changes/missing findings as Unknown. Clean count comes from the shared File Integrity summary. Monthly Critical counts use actual detection timestamps. Cleaned Files counts resolved removal records, not invented cleanup success. Quarantine counts actual preserved metadata records, including damaged records rather than hiding them. Percent growth is omitted; miniature bars are explicitly decorative. Counts include outstanding findings, which the page explains. Never scanned, pending, failed, incomplete, findings and completed/no-outstanding-findings states are distinguished; coverage errors never produce a clean banner.
14. **Quarantine.** Cleanup tools open guidance and a working link to the existing File Integrity findings/quarantine manager. It uses trusted finding IDs and server-owned artifact records. Existing SHA-256 checks, provenance, locks and preservation-before-isolation remain intact. No second quarantine store or unsafe path endpoint was introduced.
15. **Cleanup.** Remove Malware opens the review/management workflow. It does not silently delete all Suspicious findings or offer blind bulk removal. Actual containment/removal remains the existing confirmed, evidence-preserving workflow in File Integrity. The label explains this transition.
16. **Restore.** Opens the existing File Integrity manager for official core restoration or a verified retained trusted copy. Arbitrary external PHP downloads and browser-path overwrite operations were not added. Quarantined malware is not represented as a clean backup.
17. **Recent logs.** Reads only actual query firewall denials, active-lockout authentication denials and XML-RPC denials. Historical ordinary wrong-password events called “Login attempt blocked” are excluded. Five-row pages use bounded offsets and stable descending IDs. New logs store rule/path without query strings; existing authentication events show an endpoint label rather than inventing a URL. The blocked metric describes retained denial events. Query denial deduplication is best effort per visitor/rule/minute; concurrent requests can still create multiple events. It is not an exact lifetime request counter.
18. **Security.** Both new AJAX actions inherit `manage_options`, nonce verification and scalar shape checks. State values are whitelisted and persisted states verified. Existing filesystem operations retain canonical-root checks, traversal/wrapper/null/symlink rejection, source-hash verification and protected randomized evidence storage. Output is escaped; frontend templates use the existing escaping helper. Events contain no query payload, authentication secret or source preview. New query settings are independent of existing hardening/login activation, so disabling this module does not disable those services. Existing trusted proxy/IP resolution is reused.
19. **Performance.** No new chart dependency, database table, per-request scan or remote reputation/GeoIP call. Disabled query protection exits early. Enabled matching is bounded. Only denials perform log work; existing audit retention applies. Admin summaries aggregate evidence in SQL rather than loading every source evidence row. The scoped page omits the legacy WebGL hero. Asset versions use file modification time.
20. **Responsive layout.** Five desktop metrics; WAF left and scan/results right; denial table left and cleanup tools right. Tablet keeps two useful columns; mobile stacks content, wraps row text, centers the ring and uses two result columns. Tabs and tables scroll inside their own cards. Container names preserve shared header breakpoints. Native WordPress toolbar/sidebar remain native.
21. **Bugs fixed.** Shared selectors initially overrode the new Save button and typography. Scoped specificity and container names corrected this. Scanner failure rendering now survives final control cleanup. Dynamic attribute whitespace introduced during PHP formatting was removed and browser result-count parity checked. Disabling shared login protection now requires confirmation and verifies persistence. No unrelated completed-page fixes were included.
22. **Dashboard regression.** HTTP 200, correct native active submenu, one plugin application root, no browser errors. Original template, controller, provider and CSS unchanged. Dashboard data/security regression tests passed.
23. **Login Protection regression.** HTTP 200, correct active submenu, no browser errors. Original page assets/provider unchanged. Existing login lockout, allowlist and security tests passed; the new login switch uses the same existing option.
24. **Two-Factor regression.** HTTP 200, correct active submenu, no browser errors. Original page assets/provider unchanged. Two-Factor/security tests passed. The temporary browser reviewer was enrolled only on its own account; genuine user enrollment/policies were preserved.
25. **File Integrity regression.** HTTP 200, correct active submenu, no browser errors. Its view/CSS/controller and scanner/quarantine/restore services are unchanged. Shared scan summary, scan-state and workflow tests passed. Cleanup links reach its real management screen.
26. **Remaining limitations.** Query-only WAF rules can miss other encodings, authenticated attacks, bodies, oversized inputs and server-served requests that never load WordPress. No GeoIP, generic rate limiter, permanent IP-ban manager or custom-rule engine exists. Cleanup remains in the existing File Integrity management screen. Malware is a heuristic classification, not universal proof. Existing scanner coverage limits and checksum availability remain visible. Sparse real logs and different native WordPress dimensions mean the screen is not pixel-identical to populated reference data. Existing private quarantine storage retains its documented server/filesystem limitations.
27. **Tests performed.** A broad run passed 74 tests / 1,708 assertions, including new firewall tests, Security, ScanState, QuarantineManager, Restore, DashboardData, LoginProtection, TwoFactorPage, IntegrityWorkflow, UiBackend and Release suites. After later validation changes, the related subset passed 50 tests / 271 assertions, and the final firewall tests passed 5 tests / 27 assertions. Changed PHP files passed lint; JavaScript passed syntax checking. WordPress coding standards reported zero errors, with five pre-existing warnings in shared Admin/AJAX code. Browser checks covered 2560, 1920, 1600, 1440, 1366, 1280, 1024, 768, 430, 390 and 375 px, plus 1920→390→1920, 1440→768→1440 and 430→1366 without refresh. All had no page overflow. Tabs/keyboard navigation, search, management links, frontend/backend result-count parity, bad nonce rejection, settings persistence, disabling confirmation, real scan completion and native active states were verified. The intentional invalid-nonce request produced one expected browser network 403 message; page loads had no PHP warnings or JavaScript runtime errors. Anonymous SQL and XSS probes returned 403; a normal query reached WordPress. An initial probe used a server route that returned Apache 404 before WordPress; repeating via the real `index.php` entry point confirmed the firewall and actual logged events. Temporary reviewer/settings tests were cleaned up without restoring genuine users' data.
